The RUN now rewrites only the hostname in `/etc/apt/sources.list.d/pgdg.list` (same signing key, keyring already in the base), asserts the rewrite took effect via `grep`, then installs the same pinned package with the same `vector.control` build-time assert. Debian bullseye main + bullseye-security still answer 200 on `deb.debian.org`/`security.debian.org`, so no other source needs touching.

## Out

- **Actually building `consorcio-postgres:16-vector`** (`make rag-db` / `make test-rag`): forbidden here (no local docker build). Build-time risk for CI to validate: the apt-archive host swap and the `0.8.6-1.pgdg11+1` pin were verified against the live `apt-archive.postgresql.org` Packages index (200 + exact version served), not against a real build. If CI's build job fails on that layer, first suspects are (1) the archive host changing layout, (2) a future base bump leaving bullseye — at that point repin to the new suite's suffix (e.g. `pgdg12+*` for bookworm), never mix suites.
- **Moving off Debian 11 entirely** (bullseye is EOL; the whole pinned base rides a frozen archive): that is a PostGIS/pgRouting base-image bump — the compose digest, the overlay FROM, and `test_known_image_digests_are_the_ones_resolved_for_this_change` move together in one PR. Out of scope for this audit fix.
- **HSTS/CSP/rate-limit work** the deleted nginx.conf pretended to provide: prod edge is Caddy (`deploy/Caddyfile*`, covered by existing contract tests); frontend is Cloudflare Pages. Nothing to migrate.
