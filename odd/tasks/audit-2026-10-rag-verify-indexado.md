# audit-2026-10-rag-verify-indexado

Search-surface verification for `--verify-unchanged` on `feature/audit-rag4-verify-indexado` (from origin/main `e997730a`). Audit finding RAG-4 (WARNING, still open): `gee-backend/scripts/rag_ingest.py` computed a symmetric diff of sha256(`texto`) per citation key, but a parser/enrichment change under the SAME corpus SHA rewrites `texto_indexado` — the surface the FTS `tsv` is generated from and `rag_embed_batch` embeds, i.e. what BM25/FTS/embeddings actually consume — via `ON CONFLICT DO UPDATE` with `divergencias: []` and exit 0. Exactly the silent-rewrite class the flag's own comment block claims to close. RAG-3 (`activo` rotation, PR #592, merged) already touched `upsert_corpus`/`rag_ingest` nearby; this change is built on top of that merged state, not beside it.

## In

- [x] `gee-backend/app/domains/conocimiento/repository.py`: `existing_text_hashes` becomes `existing_surface_hashes`, returning `{citation_key: (sha256(texto), sha256(texto_indexado))}`. Design: SEPARATE hashes reported separately, not one combined digest — the report must name which surface moved. `texto` divergence = citation bytes changed; `texto_indexado`-only divergence = enrichment changed with the citation bytes intact. `texto_indexado` is the whole search surface (`tsv` is generated from it plus `epigrafe`, itself a joined component of `texto_indexado`, so its drift is covered transitively). The "full identity tuple" option (`tipo_chunk`/`source_offset` folded in) was evaluated and rejected in the docstring: no retrieval leg reads either column, offsets are re-derived and span-gate-validated on every parse, and folding them in would report their drift as a search-surface change it is not — the label must stay true to the hash. No schema change; read-comparison only.
- [x] `gee-backend/app/domains/conocimiento/schemas.py`: `IngestionSummary.divergencias_indexado` added (class 2 of 4, disjoint from `divergencias`: a `texto` change is classified once, as a content change); `verificacion_fallida` covers it.
- [x] `gee-backend/scripts/rag_ingest.py`: the verify block hashes both surfaces, keeps the texto-first classification, and still returns BEFORE any write including the prune (RAG2-003 delete-through-verify stays closed). `main()` prints a new class line — `superficie de búsqueda modificada (texto_indexado; el texto citado quedó igual)` — and still exits 1.
- [x] `gee-backend/tests/new/conocimiento/test_rag_ingest_cli.py`: `test_verify_unchanged_reports_indexed_surface_divergence` reproduces the audit scenario (ingest, direct DB update of `texto_indexado` only on `9750#3` — emulating the row an older parser would have written — then verify). RED-CHECK on unfixed code: `AssertionError: assert False` where the captured summary showed `divergencias=[], claves_agregadas=[], claves_eliminadas=[], committed=True` and the run fell through to the upserts (`unidades_escritas=2005`) and overwrote the divergent surface. Green after the fix: `verificacion_fallida`, `divergencias_indexado=['9750#3']`, `divergencias=[]`, nothing written/pruned, doctored row survives. Existing tests extended: pure texto change still detected and classified as content-only; identical snapshot still commits clean; the `main()` wiring test renamed to name all four classes.

## Out

Writing anything under `--verify-unchanged` beyond the existing clean-snapshot commit (the flag still upserts only when NO divergence exists); hashing `tipo_chunk`/`source_offset`/`epigrafe` as independent report classes; hashing the generated `tsv` itself (deterministic function of columns already covered); schema or migration changes; extending `--dry-run`; re-ingesting production. The verify flag also remains off by default — an operator must still pass it; making divergence detection the default ingest behavior is a policy change, not a bug fix.
