## Deviations from Design / Discoveries

1. **Full migration-chain replay is impossible on the default test image (pre-existing gap, unrelated to this slice).** The first `throwaway_db` fixture design replayed the entire migration history from empty. This immediately failed with a REAL error: `w7r4s5t6u593_add_pgrouting_canal_network.py` runs `CREATE EXTENSION IF NOT EXISTS pgrouting CASCADE` unconditionally, and the default test image (`postgis/postgis:16-3.4`) has no `pgrouting` package — a pre-existing, unrelated gap that has never been exercised because every other test in the suite builds its schema via `Base.metadata.create_all()`, never by replaying migrations. **Fix, scoped to this slice's own tests only:** the `throwaway_db` fixture now does `alembic stamp lluvia_v2_005` (the prior head) instead of replaying from empty, then `alembic upgrade head` applies only `conocimiento_001`+`conocimiento_002`. This is correctly scoped because `rag_corpus`/`rag_documento`/`rag_unidad` have zero FK dependency on any pre-existing table. **Not fixed as part of this slice** (out of scope — the pgrouting migration itself is untouched); flagging as a fact for `sdd-verify`/the orchestrator: if a future slice needs to test the FULL migration chain from empty on the vector-less image, that gap will need its own fix.
2. **Environment-coupling bug in my own tests, caught by my own verification.** After building the Docker image, I ran the FULL existing suite (not just the new tests) under `TEST_POSTGRES_IMAGE=consorcio-postgres:16-vector` as an extra check beyond what the task list required. Two of my own new tests (`test_upgrade_head_creates_three_tables`, `test_migration_002_noop_on_vector_less_image`) hardcoded "embedding column must be absent," which is only true on the vector-less image — they failed for real under the vector image. Fixed: the first test now asserts `embedding` presence against the live `ddl.extension_available()` result instead of a hardcoded expectation; the second now explicitly self-skips under a vector-capable environment (its purpose is specifically the vector-LESS no-op branch; the vector-image equivalent is 1.4's guard-symmetry test). Reran the full suite under both images after the fix: 1921 passed / 6 skipped both times, correct skip in each case.
3. **`rag_documento` PK design decision (not spelled out verbatim in design.md).** D1 explicitly gives `rag_unidad`'s PK as `(corpus_sha, citation_key)` and `rag_corpus`'s as `corpus_sha`, but does not spell out `rag_documento`'s PK. I extended the same natural-key discipline: `rag_documento` PK is `(corpus_sha, documento_id)`, with `rag_unidad` FK-ing into it via `(corpus_sha, documento_id)`. This is the minimal, consistent extension of D1's own stated principle ("every repository method takes `corpus_sha` as a required positional argument... a forgotten snapshot filter is a `TypeError`, not silent double results") — a `documento_id`-only PK would let two different corpus snapshots collide on the same document identity. Documented inline in `models.py`.
4. **`postgresql-16` gets upgraded as an apt dependency side effect.** Installing `postgresql-16-pgvector` on the base image pulled in `postgresql-16` `16.2-1.pgdg110+2` → `16.14-1.pgdg11+1` (apt resolved the newer server package as a dependency, since it wasn't pinned). This is a same-major-version patch bump (16.2 → 16.14), not a concern for a dev-only opt-in image, but worth recording: the derivative image runs a newer PostgreSQL patch release than the plain `pgrouting/pgrouting:16-3.4-3.6.1` image the rest of the stack uses.
5. **Shared `RAG_UNIDAD_TSV_EXPRESSION` constant, beyond the literal task list.** Task 1.5 scopes `ddl.py` to "the embedding DDL statements" only. To prevent the generated-tsvector expression from drifting between `models.py`'s ORM `Computed()` and migration 001's raw SQL, I defined the expression once in `models.py` (`RAG_UNIDAD_TSV_EXPRESSION`) and duplicated it verbatim (with an explicit "must stay identical" comment) into the migration rather than importing `models.py` into a migration file (avoided to keep migrations dependency-light and avoid a real import cycle risk). Not a scope violation — a direct extension of D7's own "DDL drift" concern to the one other piece of generated DDL in this slice.
